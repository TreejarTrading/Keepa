# SEARCH_GUIDE — как и по каким фильтрам искать товары

Это рабочая инструкция для поиска товаров через Keepa MCP (`/mcp` в Claude
Code). Claude читает этот файл и применяет фильтры и критерии отсюда, если в
запросе не сказано иное.

## География

Поиск ведём по 6 рынкам, в порядке приоритета (зрелость рынка):

| Приоритет | Рынок | Код | Amazon |
|---|---|---|---|
| 1 | США | `US` | amazon.com |
| 2 | Великобритания | `UK` | amazon.co.uk |
| 3 | Германия | `DE` | amazon.de |
| 4 | Франция | `FR` | amazon.fr |
| 5 | Италия | `IT` | amazon.it |
| 6 | Испания | `ES` | amazon.es |

- По умолчанию ищем в **US**. Если категория там перегрета — проверяем UK и DE
  тем же запросом (`search_multi_market`).
- ID категорий **разные на каждом рынке** — перед поиском по категории на
  новом рынке сначала `find_categories` для этого рынка.

## Базовые фильтры (профиль по умолчанию)

Если я не дал других фильтров, использовать этот профиль:

| Фильтр | Значение | Параметр инструмента |
|---|---|---|
| Цена | $15–60 | `min_price=15, max_price=60` |
| Рейтинг | ≥ 4.2 | `min_rating=4.2` |
| Отзывы | ≥ 200 | `min_review_count=200` |
| Sales rank | ≤ 60 000 | `max_sales_rank=60000` |
| Конкуренция | ≤ 15 офферов | `max_offer_count=15` |
| Продажи/мес | ≥ 200 (если задаю явно) | `min_monthly_sold=200` |

Почему так: цена ниже $15 не оставляет маржи после комиссий FBA; рейтинг ниже
4.2 — товар с проблемами; меньше 200 отзывов — спрос не подтверждён; rank выше
60k — продажи слишком редкие; больше 15 офферов — ценовая война.

Дополнительные фильтры, которые я даю в запросе, добавляются поверх профиля.
Любые нестандартные условия — через `extra_filters` (сырые ключи Keepa
Product Finder, например `{"avg90_SALES_lte": 40000}`).

## Типовые задачи и какие инструменты вызывать

1. **«Найди новые товары»** — `search_products` с базовым профилем
   (домен US, limit 15–25), затем анализ и отчёт.
2. **«Выбери категорию и найди в ней»** — `find_categories(ключевое слово)` →
   взять id → `category_best_sellers(id)` посмотреть, что реально продаётся →
   `search_products(category_id=...)` с базовым профилем.
3. **«Найди по заданным фильтрам»** — `search_products` ровно с моими
   фильтрами, базовый профиль не подмешивать.
4. **«Найди по фильтрам + мои дополнительные»** — базовый профиль +
   мои условия (через параметры или `extra_filters`).
5. **«Проверь рынок/гео»** — `search_multi_market` по US, UK, DE, FR, IT, ES.
6. **«Запусти авто-поиск»** — `run_auto_search` (см. ниже).
7. **«Что закупать / тренды / новинки»** — `discover_products` (профиль
   $20–500, домен US, `focus` = `bestsellers`/`rising`/`new`/`all`) →
   `save_buyer_report` (XLSX + DOCX со ссылками на Alibaba). См. раздел
   «Сорсинг» ниже.

## Как анализировать результаты (вердикты)

По каждому товару Claude выносит вердикт **BUY / WATCH / SKIP** + уверенность
(high/medium/low) + 2–3 ключевые метрики в обоснование + **активную ссылку на
Amazon** (в отчёте сам ASIN — кликабельная ссылка на страницу товара).

Сигналы «ЗА» (BUY):
- стабильная цена: волатильность ≤ 0.25, нет затяжного тренда вниз;
- скорость продаж: ≥ 8 просадок ранга за 30 дней или monthlySold ≥ 300;
- конкуренция умеренная: ≤ 12 офферов, Buy Box **не** у Amazon;
- рейтинг ≥ 4.2 при ≥ 100 отзывах, отзывы растут;
- понятная дифференциация по фичам, лёгкий/компактный (дешёвый FBA).

Сигналы «ПРОТИВ» (SKIP):
- волатильность ≥ 0.5 или цена стабильно падает (эрозия маржи);
- Buy Box у Amazon;
- ≥ 25 офферов (гонка на дно);
- рейтинг < 4.0 или повторяющиеся жалобы;
- слабая динамика отзывов (затухающий спрос);
- тяжёлый/габаритный товар (дорогая логистика).

Правило: ≥ 3 сигнала «против» или рейтинг < 3.8 → SKIP; ≥ 3 сигнала «за» и не
больше 1 «против» → BUY; остальное → WATCH.

**Вывод по категории**: после анализа выборки Claude даёт отдельное резюме —
стоит ли заходить в категорию (доля BUY/WATCH в выборке, средняя конкуренция,
кто держит Buy Box, ценовые уровни) и с какого товара начинать.

## Отчёты

Каждый поиск завершается `save_report` → XLSX в папку `Products/`
(на моей машине: `/home/andrea/KEEPA/Products`). Имя отчёта — краткое описание
запроса латиницей, например `us_kitchen_gadgets`.

В каждом отчёте **ячейка с ASIN — активная (кликабельная) ссылка** на страницу
товара на Amazon (`amazon.<tld>/dp/<asin>`). Отдельного текстового столбца с URL
нет — ссылку несёт сам ASIN. Конкретные пороги вердиктов — в `CLAUDE.md`.

## Сорсинг: что закупать (US → Германия/ОАЭ)

Мы возим товары $20–500 и заходим в **США** (рынок-первоисточник), чтобы найти,
что **продаётся**, что **набирает обороты** и какие есть **новинки**; те же
товары — кандидаты на сбыт в **Германии** и **ОАЭ**. Категории разные/много —
ищем широко, по фильтрам.

- Поиск: `discover_products` (по умолчанию цена $20–500, рейтинг ≥ 4.0,
  rank ≤ 80 000, домен US). `focus`: `bestsellers` (что уже продаётся),
  `rising` (моментум по рангу), `new` (новинки по `trackingSince`), `all`.
  Можно сузить через `title`/`category_id` и `extra_filters`.
- Каждый товар помечается бакетами **Bestseller / Rising / New** и получает
  `momentum_score` (сортировка «что смотреть первым»).
- Валидация спроса в **Германии** — `search_multi_market(domains=["DE"], ...)`
  или `get_products` по найденным ASIN с `domain="DE"`.
- **ОАЭ**: Keepa не отдаёт данные по amazon.ae — помечаем как рынок сбыта без
  Keepa-метрик (источник по AE — отдельно, см. `niche_analyzer/notes/AE.md`).

### Отчёт закупщику

`save_buyer_report(records, report_format="both")` → **XLSX** (фильтруемая
таблица) и **DOCX** (наглядный бриф). На каждый товар: бакет, momentum,
ключевые метрики, **кликабельный ASIN → Amazon** и **кликабельная ссылка на
поиск поставщика в Alibaba** (по ключевым словам из названия) — закупщик сразу
идёт искать поставщика. `report_format`: `both` (по умолчанию) / `xlsx` / `docx`.

## Авторежим (каждые 2 дня)

Сохранённые поиски лежат в **`auto_searches.json`** в корне проекта. Формат:

```json
{
  "searches": [
    {
      "name": "US_kitchen_gadgets",
      "domain": "US",
      "filters": {
        "title": "kitchen gadget",
        "min_price": 15, "max_price": 50,
        "min_rating": 4.2, "min_review_count": 200,
        "max_sales_rank": 60000, "max_offer_count": 15
      },
      "extra_filters": {},
      "limit": 15
    }
  ]
}
```

Запуск: вручную — `uv run keepa-auto` (или инструмент `run_auto_search` в
`/mcp`). По расписанию раз в 2 дня в 09:00 — добавить в `crontab -e`:

```
0 9 */2 * * cd /home/andrea/KEEPA && uv run keepa-auto >> auto_search.log 2>&1
```

Авторежим проставляет вердикты по правилам выше автоматически и кладёт по
одному XLSX на каждый сохранённый поиск в `Products/`. Чтобы изменить, что
ищется автоматически, — просто отредактируйте `auto_searches.json` (или
попросите Claude в чате).

## Ключ API

Ключ Keepa сервер берёт (в порядке приоритета): из переменной окружения
`KEEPA_API_KEY`, из файла `.env`, либо из файла **`ENV DOCS`** в корне проекта
(поддерживаются строки `KEEPA_API_KEY=...` или просто ключ одной строкой).
Ни один из этих файлов в git не попадает.
