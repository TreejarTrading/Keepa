# SOURCING_GUIDE — поиск товара в Китае (1688 / Alibaba / Taobao / Pinduoduo)

Это инструкция для **второго шага** воронки. Первый шаг — найти товар, который
хорошо продаётся на Amazon (через Keepa, см. [SEARCH_GUIDE.md](SEARCH_GUIDE.md))
**или** взять товар из моих данных по рынку Amazon (например, таблица
`Gold Apple Mini Fridges`). Второй шаг — **найти этот товар в Китае** и его
цену предложения: на **1688, Alibaba.com, Taobao/Tmall, Pinduoduo**.

Цель мэтчинга — **100% тот же товар (EXACT)**. Если точного товара в Китае нет —
ищем **похожие (SIMILAR)**.

## Важно: API китайских площадок нет

У 1688/Taobao/Alibaba нет такого простого открытого API, как у Keepa. Поэтому
**Claude сам заходит на сайты и ищет** — через `WebSearch` / `WebFetch` и поиск
по картинке. MCP-сервер не ходит на площадки за вас; он даёт «леса» вокруг
поиска:

| Инструмент | Что делает |
|---|---|
| `china_sourcing_plan` | По ASIN (из Keepa) и/или по моим товарам строит план: ссылки и запросы для каждой площадки + гайд, как искать. |
| `match_china_offers` | Оценивает найденные вами предложения: EXACT vs SIMILAR, считает себестоимость в USD и маржу к цене Amazon, сортирует. |
| `fetch_page` | **Запасной** best-effort GET страницы (китайские сайты часто блокируют ботов — это норма). Основной путь — ваши WebSearch/WebFetch. |
| `save_sourcing_report` | Сохраняет XLSX-отчёт в `Products/` (листы «Сорсинг» и «Сводка»). |

## Площадки (порядок приоритета по умолчанию)

| Площадка | Тип | Валюта | Язык поиска |
|---|---|---|---|
| **1688.com** | B2B опт, внутренний Китай — самые низкие цены | CNY (¥) | китайский |
| **Alibaba.com** | B2B экспорт, глобальный — FOB-цены и MOQ | USD ($) | английский |
| **Taobao / Tmall** | розница Китая — референс рыночной цены | CNY (¥) | китайский |
| **Pinduoduo** | розница / групповые покупки | CNY (¥) | китайский |

Менять список/порядок — env `CHINA_PLATFORMS` (CSV, например
`CHINA_PLATFORMS=1688,alibaba`).

## Как искать (пошагово)

1. **Подготовить товар.** Из Keepa — передать `asins` в `china_sourcing_plan`
   (название, бренд, фото и текущая цена Amazon подтянутся сами как референс).
   Из моих данных — передать `products` (название, бренд, `keywords`, `image_url`,
   `reference_price`, `currency`).
2. **Перевести название на китайский.** Для 1688/Taobao/Tmall/Pinduoduo поиск на
   китайском работает **намного** лучше. Переведите название + ключевые
   характеристики (объём, размер, материал, модель) и передайте как `query_zh`.
   Alibaba.com ищет по-английски.
3. **Сначала — поиск по картинке (для 100% мэтча).** Возьмите фото товара
   Amazon (`image_url`) и загрузите в поиск по картинке (1688 拍立淘 / Alibaba
   image search) либо сделайте reverse-image поиск. Глазами подтвердите, что это
   **тот же** физический товар.
4. **Если по картинке не вышло** — ищите по переведённому названию + бренд +
   отличительные характеристики; сравнивайте фото и габариты.
   Удобно: `WebSearch "site:1688.com <китайские ключевые слова>"` или открыть
   `search_url` из плана через `WebFetch`.
5. **Собрать предложения.** По каждому фиксируйте:
   - `platform`, `supplier` (магазин/фабрика), `title` и `title_en` (перевод);
   - `unit_price` + `currency` (CNY на 1688/Taobao/PDD, USD на Alibaba), `moq`, `url`;
   - `image_confirmed: true` (+ `image_score` 0–1), если убедились по фото, что товар тот же;
   - `brand`, если указан.
6. **Оценить.** Передайте товар и список предложений в `match_china_offers` —
   он проставит EXACT/SIMILAR, посчитает себестоимость и маржу. Хотите учесть
   доставку — `freight_pct` (например `0.15` = +15% к цене), плюс
   `extra_cost_usd` для фикс. затрат на единицу.
7. **Сохранить отчёт.** `save_sourcing_report` с результатами `match_china_offers`.

## EXACT vs SIMILAR

- **EXACT (~100%)** — тот же физический товар: подтверждено по картинке
  (`image_confirmed`) либо очень высокое совпадение названия/характеристик
  (порог `CHINA_EXACT_THRESHOLD`, по умолчанию `0.9`).
- **SIMILAR** — близкий аналог. Берём, когда точного нет.

Сервер считает `match_score` и ставит тип сам, но финальное «тот же / не тот же»
решаете вы по фото. Китайские названия по-английски не мэтчатся текстом — для
них главный сигнал EXACT это **подтверждение по картинке** (или `title_en`).

## Экономика (грубая оценка)

Сервер переводит цену предложения в USD по курсам из конфига, прибавляет
`freight_pct`, и считает маржу к цене Amazon:

```
landed_usd = unit_price→USD × (1 + freight_pct) + extra_cost_usd
margin_%   = (Amazon_price→USD − landed_usd) / Amazon_price→USD
```

Это **оценка** — перед закупкой проверяйте реальную доставку, пошлины и комиссии
Amazon/FBA. Курсы валют (дрейфуют со временем) — env `CHINA_USD_PER_CNY`
(юань→USD, по умолчанию `0.14`) или полная карта `CHINA_FX_TO_USD` (JSON).

## Отчёт

`save_sourcing_report` пишет XLSX в `Products/`:

- **Сорсинг** — по строке на предложение: площадка, поставщик, название, тип
  мэтча (EXACT зелёный / SIMILAR жёлтый), score, цена + валюта, цена в USD,
  себестоимость, маржа %, MOQ, ссылка.
- **Сводка** — итоги (сколько товаров, предложений, у скольких найден EXACT) и
  лучшее EXACT/SIMILAR-предложение по каждому товару.

## Пример запроса в `/mcp`

> «Возьми BUY-товары из последнего отчёта Keepa и найди их в Китае. Сначала по
> фото для точного совпадения, иначе похожие. Посчитай маржу с доставкой 15% и
> сохрани отчёт по сорсингу.»

Claude: `china_sourcing_plan(asins=[...])` → переводит названия, ищет на
1688/Alibaba/Taobao по картинке и тексту через WebSearch/WebFetch → собирает
предложения → `match_china_offers(..., freight_pct=0.15)` → `save_sourcing_report`.
