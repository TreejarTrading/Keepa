# KEEPA — сервис поиска и аналитики товаров Amazon

MCP-сервер, который ищет товары на Amazon через **Keepa API**, вытягивает
метрики для принятия решения о закупке (история цен, скорость продаж,
конкуренция, рейтинги, характеристики) и формирует **XLSX-отчёты** в папку
`Продукты/`. Сам анализ и вердикт **BUY / WATCH / SKIP** выносит Claude через
`/mcp`, опираясь на возвращаемые метрики, отзывы и характеристики.

## Что внутри

```
KEEPA/
├── .mcp.json                # регистрация сервера для Claude Code (/mcp)
├── .env.example             # шаблон переменных окружения (ключ Keepa и пр.)
├── pyproject.toml           # пакет keepa-mcp (uv / pip)
├── src/keepa_mcp/
│   ├── config.py            # конфигурация из окружения
│   ├── keepa_client.py      # обёртка над Keepa API (поиск + детали)
│   ├── analysis.py          # извлечение метрик решения из данных Keepa
│   ├── reports.py           # генерация XLSX-отчётов
│   └── server.py            # MCP-сервер (FastMCP) и его инструменты
├── Продукты/                # сюда складываются XLSX-отчёты
└── tests/                   # офлайн-тесты (без обращения к API)
```

## Установка

Нужен [`uv`](https://docs.astral.sh/uv/) (или обычный `pip`) и Python ≥ 3.10.

```bash
uv venv
uv pip install -e .
```

## Настройка

1. Скопируйте `.env.example` в `.env` и впишите ключ Keepa:

   ```bash
   cp .env.example .env
   # KEEPA_API_KEY=ваш_ключ        (получить: https://keepa.com/#!api)
   ```

2. Маркетплейс по умолчанию — **Amazon.com (US)**. Сменить можно через
   `KEEPA_DOMAIN` (US/UK/DE/FR/JP/CA/IT/ES/IN/MX).

3. Отчёты по умолчанию пишутся в `<repo>/Продукты`. Так как на рабочей машине
   репозиторий лежит в `E:/KEEPA`, путь автоматически совпадает с
   `E:/KEEPA/Продукты`. Переопределить — переменной `KEEPA_OUTPUT_DIR`.

## Запуск через `/mcp` в Claude Code

Файл `.mcp.json` уже описывает сервер. Откройте Claude Code в папке проекта,
выполните `/mcp` — сервер `keepa` появится в списке. Дальше можно просить, например:

> «Найди беспроводные наушники до $40 с рейтингом от 4.3 и хотя бы 500 отзывами,
> проанализируй и сохрани отчёт».

Claude вызовет инструменты сервера, проанализирует метрики и сохранит XLSX
в `Продукты/`.

### Инструменты MCP

| Инструмент | Назначение |
|---|---|
| `server_info` | Текущая конфигурация (маркетплейс, папка отчётов, наличие ключа). |
| `token_status` | Остаток токенов Keepa (квота). |
| `search_products` | Поиск через Keepa Product Finder + метрики по найденным ASIN. |
| `get_products` | Полные метрики и характеристики по известным ASIN. |
| `analyze_and_report` | Загрузить метрики по ASIN, сразу сохранить отчёт, вернуть данные. |
| `save_report` | Сохранить XLSX-отчёт с вердиктами, проставленными Claude. |

### Типичный сценарий

1. `search_products(...)` — найти кандидатов и получить метрики.
2. Claude анализирует: история цен, волатильность, скорость продаж
   (просадки ранга), конкуренция (число офферов, Buy Box), рейтинг и динамика
   отзывов, характеристики и закрытие потребностей покупателя.
3. Claude проставляет каждому товару `verdict` / `confidence` / `rationale`.
4. `save_report(records=...)` — сохранить итоговый XLSX в `Продукты/`.

## Метрики и логика решения

Сервер возвращает по каждому товару:

- **Цены**: текущая/средняя/мин/макс и волатильность для New, Amazon, Buy Box, FBA.
- **Скорость продаж**: текущий sales rank и число просадок ранга за 30/90 дней
  (прокси числа продаж), оценка `monthlySold`.
- **Конкуренция**: число офферов, держит ли Buy Box сам Amazon.
- **Спрос/удовлетворённость**: рейтинг и его динамика, число и скорость отзывов.
- **Характеристики**: бренд, категория, фичи, описание, габариты/вес, вариации,
  оценка комиссий FBA.

Вместе с данными отдаётся `DECISION_GUIDANCE` — набор сигналов «за» и «против»,
чтобы вердикты Claude были единообразными. Итоговое решение всегда за Claude.

## Безопасность

`.env` с ключом Keepa в git не попадает (`.gitignore`). XLSX-отчёты тоже
игнорируются — в репозитории остаётся только сама папка `Продукты/`.
